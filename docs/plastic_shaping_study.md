# Identification and plastic shaping study

The active manuscript is `paper/icra2027/paper.tex`. Its shaping figure is generated by
`experiments/robotics/plastic_shaping_figure.py` from the saved outputs of
`experiments/robotics/plastic_shaping_study.py`. The historical
`examples/gripper_shape.py` and its rendering scripts do not generate this figure.

To regenerate the manuscript figure from the saved original study and rebuild
the PDF, run from the repository root:

```bash
.venv/bin/python -m experiments.robotics.plastic_shaping_figure
./paper/icra2027/build.sh
```

The figure generator defaults to `paper/icra2027/figs/identification_plastic_shaping`
(PDF and PNG). The compiled manuscript is `paper/icra2027/paper.pdf`.

## Reproduce from scratch

From the repository root, use the project Python environment and an available GPU.
The original run uses `cuda:1` on an NVIDIA RTX 5090. GPU 0 was occupied by other work.
Use a new output directory to avoid reusing any trajectories:

```bash
STUDY_OUT=out/plastic_shaping_reproduction
STUDY_DEVICE=cuda:1
.venv/bin/python -m experiments.robotics.plastic_shaping_study prepare --out "$STUDY_OUT" --device "$STUDY_DEVICE"
.venv/bin/python -m experiments.robotics.plastic_shaping_study run --out "$STUDY_OUT" --device "$STUDY_DEVICE"
.venv/bin/python -m experiments.robotics.plastic_shaping_study numerics --out "$STUDY_OUT" --device "$STUDY_DEVICE"
.venv/bin/python -m experiments.robotics.plastic_shaping_figure --out "$STUDY_OUT" --dest "$STUDY_OUT/identification_plastic_shaping"
.venv/bin/python -m experiments.robotics.plastic_shaping_study verify --out "$STUDY_OUT"
```

`prepare` simulates a fresh probe for each material, fits from its saved state
observations, and predicts the independent validation press. `run` creates targets,
evaluates the action libraries, selects plans, and executes them with the true
material parameters. It can resume at completed library files. `verify` recomputes
the reported errors, checks action selection, compares every execution to an
independent true-material rollout, and writes file checksums and environment data.
CUDA atomic accumulation can cause small floating-point differences; numerical
reproduction does not mean byte-identical particle trajectories.
Resume only with the same code, protocol, and fitted parameters. Use a fresh
output root when changing any scientific setting; cached trajectories are not
an experiment with the new setting.

The original output root is `out/plastic_shaping_20260908`; final evidence is in
its `study/` directory. `pilot/` contains explicitly separate exploratory runs,
including unsuccessful historical-estimator and historical-gripper trials.
The final A and B probe trajectories reuse the identical pilot protocols and are
refitted from their observations. A fresh `prepare` generates them directly and
does not require the pilot files.

## Frozen experiment

Two initially identical blocks have a perfectly plastic von Mises material with
Hencky elasticity. Both have Young's modulus 80 kPa, Poisson's ratio 0.30, and
density 1000 kg/m³. A has yield threshold 1 kPa and B has threshold 10 kPa, defined
as the Frobenius norm of deviatoric Kirchhoff stress, matching the engine and
the manuscript. This study identifies parameters within a supplied family; it
does not select between constitutive families.

The domain is a 0.30 m cube with a 48³ grid. The nominal specimen size is
120 × 80 × 60 mm, sampled at two particles per cell direction with jitter seed 0.
Both specimens use exactly the same initial particle positions and volumes.
The fixed floor is sticky. Grippers and the plate are kinematic box colliders
that impose their velocity on covered grid nodes. The timestep is 0.1 ms and
the control period is 0.8 ms. Particle sorting is off, preserving particle IDs.

The calibration probe presses down 14 mm at approximately 80 mm/s. Its sampled
positions, velocities, elastic deformation gradients, reference volumes, and
masses are the observations supplied to identification. Neither pressure nor
stress labels are supplied. The Hencky stress columns enter the existing
time-integrated weak momentum balance, fitting shear and Lamé moduli. We use
every second frame, overlapping 26-frame windows, four spatial modes, and a
two-cell exclusion margin from the floor and the deepest plate position.
The elastic-strain plateau then estimates yield using the fitted shear modulus.
The existing plateau detector's limitations still apply; the probe is continuous
loading and the simulated materials actually reach yield.

The held-out press moves 24 mm at approximately 120 mm/s. Its force curves do not
enter identification or parameter selection. Force error is the relative L2 norm
over the entire saved curve, including initial loading. The shared nominal model
uses the correct elastic parameters and yield threshold 5.5 kPa, the arithmetic
midpoint of the two thresholds. It therefore isolates a yield mismatch without
adding an elastic-stiffness error to the baseline.

Shaping uses two centered orthogonal gripper squeezes, first x then y. Each finger
moves at approximately 100 mm/s, with exact final gaps enforced by adjusting the
last discretized duration's constant speed. Separate collider pairs have the
correct orientation for each squeeze. Both fingers are removed after each squeeze,
followed by 0.30 s of free evolution. Outcomes are measured at that specified delay,
not asserted to be fully static equilibrium shapes.

Each model evaluates the same 121 candidate gap pairs: 11 x-gaps from 60 to 100 mm
and 11 y-gaps from 50 to 90 mm. Exhaustive selection is deterministic, with the
same candidate set and objective for nominal, identified, and true-parameter models.
Libraries are reused across targets as a computation cache; this does not change
which candidates a model can select.

Three target shapes per material are generated by gap pairs (67, 58), (83, 74),
and (93, 66) mm. These pairs are not in the candidate library. Target generation
uses the true material to establish feasible goals; only the resulting particle
cloud is passed to the planner. The targets are material-specific, so there are
six material/target tasks rather than three common target geometries. The figure
shows the first target for each material, fixed before evaluating outcomes.

Every selected plan, including a plan chosen by the identified model, is executed
again in that specimen's true material. The shape objective and reported error
are the mean of the two mean Euclidean nearest-neighbor distances between the
complete 3D particle clouds, expressed in millimetres. There is no alignment,
rescaling, subsampling, squaring, or factor-of-two convention hidden in the metric.
The three methods have six task errors each. These are deterministic tasks, not
independent noisy repetitions; the figure does not attach statistical confidence
intervals to them. The true-parameter result measures finite-action-set limitations.

## Outputs and provenance

- `protocol.json`: material values, geometry, actions, observation scope, metric.
- `probe_A.npz`, `probe_B.npz`: calibration trajectories and snapshots.
- `identification_*.json`: fitted parameters, residuals, and plateau diagnostics.
- `validation_*.npz`: held-out true, identified, and nominal press rollouts.
- `target_*.npz`: true-material target clouds and intermediate snapshots.
- `library/<model>/*.npz`: every candidate rollout, indexed by `candidate_actions`.
- `execution_*.npz`: actual true-material executions used for the action sequence
  in panel (c) and the final outcomes in panel (d).
- `shaping_results.json`: all candidate errors, selected actions, and execution errors.
- `summary.json`: aggregate shaping and force errors.
- `figure_provenance.json`: renderer and result hashes, surface settings, figure hashes.
- `provenance.json`, `source_snapshot/`, `environment.*`, `gpu.csv`: code and runtime records.
- `verification.json`, `checksums.json`: verification results and artifact hashes.

For reproduction in a separate checkout, use the recorded Git commit together
with the archived `source_snapshot/final/` files and recorded package versions.
The commit alone is insufficient: before this study, the working tree already
contained a one-line docstring-closure repair in `src/ident/weakform/elastic_grid.py`.
The archived copy includes that repair. The simulator and identifier source
hashes are checked against those recorded when the experiment was launched.

Rendering uses a fixed physical density-smoothing scale and isovalue, with shared
cameras and lighting. Both initial specimens have the same material appearance.
The target silhouette is projected into a saved binary mask and overlaid on the
actual executed outcomes as a 0.55 pt dashed black vector contour, with no white
surround. The gaps leave the actual boundary visible. All six outcome views use
the same closer orthographic framing, with at least 5 mm of vertical clearance
around the union of their projected surfaces. The target and execution use the
same camera, without registration or distortion. Numerical metrics are computed
from raw particles, independently of surface reconstruction.
Panel (c) shows the saved first-target identified-plan execution for material A:
the x squeeze, the y squeeze, and the final released shape. Its translucent tools
use the recorded collider centers and half-extents, with enlarged black arrows
marking closing directions. Arrow length is illustrative, with tips fixed at the
same locations. The press uses the protocol's plate dimensions, with a schematic
mount above the plate to illustrate actuation. This mount is visual only and is
identified as schematic in the caption. Initial and compressed snapshots share
a fixed actuator head, with shaft extension equal to the recorded 14 mm stroke.
The compressed view overlays a blue outline of the plate's initial position,
rendered with a 0.8 mm tube radius so its stroke survives reduction to paper size;
no press-direction arrow is used. The figure uses four equally sized panels
on an aligned 2 × 2 grid. Panel (c) lists the illustrated action's closing gaps;
panel (d) labels each displayed outcome with its executed error. Aggregate errors
remain in the manuscript text. All snapshots within each panel share a camera
and physical scale.

## Checks and scientific scope

Run the focused checks with:

```bash
.venv/bin/pytest -q tests/test_plastic_shaping_study.py tests/test_elastic_grid.py
```

The study tests specifically cover the orthogonal-finger orientation bug, the
symmetric unsquared millimetre metric, and target actions being absent from the
candidate set. Existing weak-form tests cover assembly, contact-node exclusion,
stress/volume pairing, and load signs.

`numerics` keeps the selected first-target actions fixed and repeats target
generation and true-material execution at a 0.05 ms timestep and, separately,
on a 64³ grid. It writes `numerical_sensitivity.json` and the corresponding raw
trajectories. This is a sensitivity check on two tasks, not a convergence study.

This is a noiseless same-engine simulation study with supplied elastic states,
known geometry, density, and contact. It supports transfer to changed actions
within this material family. It does not establish identification from appearance,
positions alone, real force sensors, unknown contact, or a different simulator.
The planner selects a two-squeeze open-loop action sequence; it is not closed-loop
model-predictive control. No old press accuracy, sixfold improvement, or Table II
timing is imported into this experiment.

The old force-based press estimator and old gripper renderer are left intact for
historical provenance. In particular, the new gripper implementation corrects the
old demo's failure to rotate collider half-extents for its y-directed squeeze;
its separate implementation does not silently change archived demonstrations.

A subsequent [hexagonal-shaping pilot](hex_shaping_pilot.md) tested a possible
figure replacement. Its released shapes did not meet the geometry criterion for
both materials, so the rectangular figure was retained at that stage.
A later [optimized-gap experiment](hex_shaping_control.md) obtained rounded
hexagonal prisms for both materials by increasing B's stiffness. It establishes
known-parameter feasibility. The subsequent [hexagonal identification study](hex_shaping_study.md)
reruns identification and planner comparisons for the revised material and
supersedes this rectangular example in the active manuscript. The data and
results documented above remain archived unchanged.
